Assignment

Build Your Own JSON Serializer

Build a JSON serializer and deserializer from scratch in C# — no libraries doing the real work for you. By the end, you'll understand exactly what tools like System.Text.Json are doing internally, because you'll have built a working version yourself.

Overview

You'll build a library that turns C# objects into JSON text, and JSON text back into C# objects. You may not use System.Text.Json, Newtonsoft.Json, or any other JSON library for the core work.

Use reflection to inspect an object's properties for serialization, and to populate them during deserialization. Don't hand-write per-class conversion code — the library should work on any class through reflection alone.

Not allowed: System.Text.Json, Newtonsoft.Json/Json.NET, or any third-party JSON library.
Allowed: reflection, generics, collections, StringBuilder, regular expressions — anything else in the base class library.

1. Basic Serialization

Serialize primitive values: string, int, long, float, double, decimal, bool, and null.

2. Object Serialization

Given a plain class:

public class User
{
    public int Id { get; set; }
    public string Name { get; set; }
    public bool IsActive { get; set; }
}

Serializing an instance should produce:

{
  "Id": 1,
  "Name": "John",
  "IsActive": true
}

Discover the properties dynamically — don't hand-write serialization code per class.

3. Nested Objects

Objects containing other objects should nest correctly in the output, at any depth.

4. Collections

Support arrays, List<T>, and IEnumerable<T>. Collections can hold primitives, objects, or other collections.

5. Dictionaries

Support Dictionary<string, object>, serialized as a JSON object.

6. Deserialization

Convert JSON back into a typed object:

var user = JsonSerializer.Deserialize<User>(json);

7. Reading JSON

Your code needs to turn JSON text — objects, arrays, strings, numbers, booleans, null — back into C# values. Malformed JSON should raise a clear error, never silently produce a "valid-looking" object.

8. Special Types

Support DateTime, Guid, enum, and nullable value types (int?). There's no single correct representation for most of these — make a reasonable call and document it.

9. Error Handling

Handle bad input gracefully: invalid JSON, unexpected tokens, malformed numbers, type mismatches on deserialization. Exceptions should say what went wrong, not just "something failed."

10. Circular References

An object can end up referencing itself, directly or through a chain:

person.Friend = person;

Your serializer must not infinite-loop on this. Detect it, handle it reasonably, and document your choice.

Performance

Serialize the same type thousands of times in a loop and see where the time goes — reflection lookups are the usual culprit. Optimize what's actually expensive (metadata caching is a common fix) and back it up with a small before/after benchmark.

Deliverables

  • Source code for the library
  • README.md: how to use it, supported types, design decisions, limitations, how circular references and errors are handled
  • A short performance report
